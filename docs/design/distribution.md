# Distribution — Atari `.ST` floppy images + hard-drive installer

How to turn a built engine + packs into a redistributable set of Atari floppy
images that install and run on real hardware (or a Gotek/HxC floppy emulator, or
an emulator). **We ship no copyrighted data** — the images are built from the
user's own original Ultima VI files and are gitignored; only the builder script,
the installer source, and this doc are committed.

Implemented by: [`scripts/make-st-disks.sh`](../../scripts/make-st-disks.sh),
[`installer/install.c`](../../installer/install.c) (→ `INSTALL.TOS`).
Make targets: `st-disks`, `st-disks-falcon`, `st-disks-st`, `st-disks-tt`.

## Why an installer (and disk-spanning)
The game loads its data by bare filename via GEMDOS `Fopen` (opcode 0x3D), so
the packs must sit **in the same folder as the `.PRG`** on the target drive. The
full 256-colour `U6.PAK` is ~2.4 MB — **bigger than a 1.44 MB floppy** — so a
single file cannot live on one disk. The builder therefore:

1. splits oversized packs into cluster-aligned parts that each fit a floppy, and
2. ships `INSTALL.TOS`, which **reassembles** the parts (and copies the whole
   files) onto a hard-drive/CF folder, prompting for disk swaps.

The ST/TT slim packs (`U6ST.PAK`/`U6TT.PAK` ~1.08 MB, streamed `U6FE.PAK`
~1.40 MB) each fit one floppy, but they are packed and reassembled by the same
generic mechanism.

## What goes in a distribution (U6)
Per target, the installed folder ends up with:
- the engine `.PRG` — `GAMEF.PRG` (Falcon) / `GAMEST.PRG` (ST) / `GAMETT.PRG` (TT)
- the pack(s) — `U6.PAK` (Falcon) or `U6ST.PAK`+`U6FE.PAK` / `U6TT.PAK`+`U6FE.PAK`
- `CONVERSE.A`, `CONVERSE.B`, `PORTRAIT.A`, `PORTRAIT.B` — NPC dialogue + faces,
  which the engine loads as **separate files** (see `gamedemo.c`, kept out of the
  pack so they land in ST-RAM); copied verbatim from your `refdata`.
- `MENU.REQ` (1 byte) — presence tells the engine to boot to the U6 **title /
  main menu** (Introduction / Create a Character / Journey Onward) instead of
  dropping straight into gameplay. This is the authentic interactive boot.
- `README.TXT`

Not yet included: **music** (`MIDI.DAT` + `.M` songs) is not packaged yet — the
game degrades gracefully to silence. (Tracked with the M10 music loose ends.)

The engine's many `*.REQ` / `*.BIN` files are debug/headless-test sentinels and
are **not** shipped (their absence = normal play).

## Disk images
- Standard PC/Atari **FAT12**, created with `mformat` (mtools). Geometry matches a
  stock 1.44 MB disk (512 B/sector, 2880 sectors, 2 FATs, 18 sec/track, 2 heads)
  — byte-identical BPB to disks that already work on the user's Gotek. Non-boot
  data disks: TOS mounts them via GEMDOS, no boot-sector code needed.
- `--size 720` produces 720 KB DD images instead (e.g. a stock Mega ST drive).
- Volume labels: `U6ATARI` (disk 1), `U6DATA<n>` (data disks).
- Filenames: `<name>-<target>-disk<n>.st` (default name `u6`).

Disk 1 always holds `INSTALL.TOS`, `INSTALL.INF`, `README.TXT`, `MENU.REQ`, and
the engine `.PRG`, then as much data as fits; the rest flows onto disks 2..N. The
packer fills each disk greedily, so a big pack's first part shares disk 1 with the
engine and the tail spills onto later disks. Typical Falcon result: **3 disks**.

## Installer manifest (`INSTALL.INF`)
Plain text, generated by the builder, read by `INSTALL.TOS` from disk 1. One
directive per line (`;`/`#` = comment):

```
TITLE <free text>          banner
DEST  <path>               default install folder (e.g. C:\U6)
AUTO  1                    optional: install to DEST without prompting
OUT   <destname>           begin an output file in DEST
SRC   <disk#> <srcname>    a source part on floppy <disk#>, appended in order
END
```

A whole file is one `SRC`; a split pack is several `SRC` lines (one per part,
each tagged with the floppy it lives on) that the installer concatenates. A
command-line argument to `INSTALL.TTP` also sets the folder and runs
non-interactively.

TOS/GEMDOS calls used by the installer (name + opcode, TRAP #1): `Cconws` 0x09,
`Cnecin` 0x08, `Cconrs` 0x0A, `Dgetdrv` 0x19, `Dcreate` 0x39, `Fopen` 0x3D,
`Fcreate` 0x3C, `Fread` 0x3F, `Fwrite` 0x40, `Fclose` 0x3E. No AES/VDI/XBIOS, no
supervisor mode; the DMA copy buffer is `static` (BSS → ST-RAM, chip-accessible).

## Building
```
# from your own refdata/ (see refdata/README.md); builds packs then images:
make st-disks-falcon
# write straight to a Gotek SD / mounted card as well:
make st-disks-falcon STDISK_ARGS='--media /run/media/<you>/<card>/Atari'
# other machines:
make st-disks-st        # Mega ST / STE (16-colour)
make st-disks-tt        # TT030 (256-colour)
```

## Verification (done)
- **Split integrity**: the builder reassembles every split pack host-side and
  asserts it is byte-identical to the original before writing images.
- **Round-trip from images**: extracting the parts *from the `.st` images* and
  concatenating reproduces `U6.PAK` with a matching SHA-256.
- **Installer on real TOS**: run headless under Hatari (Falcon, TOS 4.04), the
  installer parses the manifest, creates the folder, copies the whole files, and
  reassembles a byte-exact `U6.PAK`; aux files match `refdata` byte-for-byte.
- **Boot from the installed set**: the game boots that folder to the authentic
  "Ultima VI" title menu (VIDEL 320×240, TOS 4.04).
